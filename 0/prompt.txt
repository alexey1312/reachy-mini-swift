### `Sources/ReachyKit/Transport/RobotConnection.swift`
**A1 fix** — the hardware id is the BLE↔LAN join key and was being mangled:
```swift
/// An unsupported version is reported, not thrown. The daemon's own update route
/// is the way out of that state, and throwing here left the user on a "Try again"
/// button that could never work. `RobotSession` gates the command surface on the
/// verdict instead — see ADR 0001.
public func handshake() async throws -> Handshake {
    let status = try await daemonStatus()
    let compatibility = DaemonCompatibilityPolicy.evaluate(status.version)
    let hardwareID = await hardwareID(reportedIn: status)
    let name = try? await client.getRobotDisplayNameApiDaemonRobotNameGet().ok.body.json.name
    return Handshake(
        identity: RobotIdentity(hardwareID: hardwareID, name: name ?? status.robotName,
                                daemonVersion: status.version),
        status: status, compatibility: compatibility
    )
}

private func hardwareID(reportedIn status: Components.Schemas.DaemonStatus) async -> String? {
    if let reported = status.hardwareId, !reported.isEmpty { return reported }
    let map = try? await client.getRobotHardwareIdApiDaemonHardwareIdGet()
        .ok.body.json.additionalProperties
    return map?["hardware_id"].flatMap { $0.isEmpty ? nil : $0 }
}
```

```swift
static func makeSession(_ stubs: [String: Stub]) -> URLSession {
    let token = UUID().uuidString
    lock.withLock { sessions[token] = stubs }
    let configuration = URLSessionConfiguration.ephemeral
    configuration.protocolClasses = [StubURLProtocol.self]
    configuration.httpAdditionalHeaders = [tokenHeader: token]
    return URLSession(configuration: configuration)
}

private static func stub(for request: URLRequest) -> Stub? {
    guard let token = request.value(forHTTPHeaderField: tokenHeader),
          let url = request.url,
          let table = lock.withLock({ sessions[token] })
    else { return nil }
    if let query = url.query(), let narrow = table["\(url.path)?\(query)"] { return narrow }
    return table[url.path]
}
```

### `Sources/ReachyKit/Session/RobotSession+ConnectionStage.swift` (rewritten to fix complexity)
```swift
private extension RobotSession.ConnectionStep {
    var position: (stage: RobotSession.ConnectionStage, outcome: RobotSession.StageOutcome) {
        switch self {
        case .handshaking: (.connect, .active)
        case .checkingBackend: (.backend, .active)
        case .needsDaemonUpdate: (.compatibility, .attention)
        case .backendUnavailable: (.backend, .attention)
        case let .failed(stage, _): (stage, .failed)
        }
    }
    func outcome(for stage: RobotSession.ConnectionStage) -> RobotSession.StageOutcome {
        let current = position
        guard stage != current.stage else { return current.outcome }
        return stage.rawValue < current.stage.rawValue ? .done : .pending
    }
}
```

## 4. Errors and Fixes

1. **Three test failures from a latent parallelism race** — `StubURLProtocol` held stubs in a global static; `swift test --parallel` runs *suites* concurrently and `.serialized` only orders within one suite. My new suite turned the latent race into deterministic failure. **Fix:** bound stubs to their session via an `X-Stub-Session` header token.

2. **Hung test (600 s timeout, killed)** — in `UpdateLogStreamClientTests` I concatenated two raw strings and left a stray `"`, producing malformed JSON, so the awaited event never arrived. **Fix:** used a triple-quoted literal and added `.timeLimit(.minutes(1))` to every async test.

3. **`closesOnceWhenTheDaemonRestarts` lost its frame** — `connection.cancel()` raced the `.idempotent` send. **Fix:** added a `then:` completion to `LocalWebSocketServer.sendText` using `.contentProcessed`, so the test waits on the condition rather than racing it.

4. **`cannot find '$model' in scope`** — passing an `@Observable` as `let` gives no projected value. **Fix:** `@Bindable var model: LogConsoleModel`.

5. **`UpdateStubClient` does not conform to `RobotAPIClient`** — `handshake`, `daemonStatus`, `wakeUp`, `gotoSleep` have no defaults. **Fix:** implemented `wakeUp`/`gotoSleep`. Recorded in `Sources/ReachyKit/AGENTS.md`.

## 5. Problem Solving

**Solved:**
- Established that the original desktop app does NOT use BLE for provisioning (it uses SoftAP + plaintext HTTP), and that the robot-side BLE protocol was purpose-built for mobile clients — we would be its first consumer.
- Verified daemon 1.9.0 (our existing minimum) already ships everything needed — no version-policy change.
- **Corrected upstream's own documentation**: `BLE_WIFI_PROVISIONING.md` claims all commands notify; the code shows synchronous commands answer only on a read. A client written to the doc would hang on `PING`.
- Discovered `/update/ws/logs` sends both raw lines and repeating JSON frames.
- Discovered `sim-daemon --wireless-version` cannot work (missing `nmcli`/`cryptography`; host-side robot-image maintenance).
- Found and fixed a pre-existing hardware-id mangling bug that would have silently broken the BLE↔LAN handoff.
- Produced a cross-implementation known-answer vector for the sealing crypto.

**Open risk (documented, not resolved):** `WIFI_CONNECT_ENC` is ~260 bytes against iOS's default ATT MTU of 185, and the robot's handler ignores write offsets. The plan makes measuring `maximumWriteValueLength(for: .withResponse)` on hardware **step 0**, before anything is built on top of provisioning. `WiFiProvisioningTransport` exists in the design so an HTTP-over-hotspot fallback can be swapped in.
